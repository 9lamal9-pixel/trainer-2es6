# Разработка тренажера 2ЭС6

Это рабочая среда WinForms/.NET Framework x86 поверх копии штатных DLL.
Сначала прочитай `dev/environment-context.json` и `dev/state/context.json`.
При отсутствии динамического состояния выполни `dev/TrainerDev.ps1 -Action Handoff`.
Стартовые JSON читай один раз за сеанс; при изменении состояния перечитай динамический контекст.
Готовый стартовый промпт: `BOT_PROMPT.txt`; локальные документы: `dev/config/references.json`.
Дальше открывай только нужные разделы каталогов и относящиеся к изменению исходники.

Канонические C# исходники находятся в `outputs`; проект связывает эти же файлы.
Native runtime: `work/trenager_static/WORK_TRENAGER_3D`.
Не изменяй исходную установку `E:\WORK_TRENAGER_3D` и не используй computer use.
Нативные исправления выполняются в памяти с SHA/byte guards и восстановлением.

Используй `dev/TrainerDev.ps1`: Doctor, Build, Test, Run, Fix, Checkpoint, Handoff, Status, Archive.
Fix объединяет сборку, выбранные проверки, сохранение исправления и обновление контекста.
Имена проб и ограничения: `dev/config/probes.json`; подбор области: `test_areas` в индексе.
Для запуска EXE используй Run: native пути рассчитаны на deployment в `outputs`.
Нативные Run/Test выполняй с обычным доступом Windows: песочница может вызвать `InitCommunication=200` ещё до сценария. Это отказ инициализации; для приёмки нужен новый успешный прогон с нужным доступом, подробности — `dev/docs/MIGRATION.md`.

Ищи узким `rg` в выбранных файлах. Не читай целиком телеметрию, bitmap blobs и исторические findings.
Для состояния используй компактные report/result/session, последние строки журналов и динамический JSON.
Запускай проверки последовательно; нужны exit code 0, assertions и новые ожидаемые результаты.
Не используй старый файл результата как доказательство нового прохождения.
Повторяй/расширяй проверки после изменений, ошибок или нерешенной неопределенности.
Сохраняй причину правки, результат проверки и ограничения в checkpoint; неуспехи сохраняются в runs.

Точная ревизия РЭ/комплектация 2ЭС6 начиная с №137 еще не установлена.
Зеленая регрессия подтверждает описанные сценарии, не полное соответствие всей модели РЭ.
Полный холодный пуск до зарядки ПМ, расход приводов и ряд калибровок остаются в backlog.
`ColdNativeInitialization fresh` небезопасен; устаревшие пробы каталога не применять для приемки.

Текущий корень среды указан в `workspace.root` индекса.
Исторические абсолютные пути сохраняют происхождение; сопоставление после переноса — `dev/config/relocation.json`.
Не запускай старые Install/Apply-скрипты, физически изменяющие DLL. Для запуска команд из корня можно использовать `trainer.cmd`.
