# Полная среда на другом компьютере

Исходники хранятся в приватном репозитории [trainer-2es6](https://github.com/9lamal9-pixel/trainer-2es6), крупные файлы — в [Release trainer-environment-2026-10-16](https://github.com/9lamal9-pixel/trainer-2es6/releases/tag/trainer-environment-2026-10-16). Это снимок среды разработки, а не подтверждение полного соответствия модели РЭ. АВП остаётся отключённым до завершения калибровки и приёмки.

## Подготовка

Нужны Windows x64 (AMD64), Windows PowerShell 5.1, Git for Windows и .NET Framework 4.x с 32-битным компилятором. Python 3.13.16 x64 вместе с pefile, capstone и pip входит в комплект Release; отдельно устанавливать Python для обычной подготовки не требуется. IDE необязательна: проект можно открыть в Visual Studio или VS Code. Права администратора для скрипта не требуются; установка отсутствующих системных компонентов выполняется отдельно.

1. Авторизуйтесь в GitHub с доступом к приватному репозиторию: через Git Credential Manager либо командой `gh auth login`.
2. Склонируйте репозиторий в короткий путь, например C:\trainer, и переключитесь на ветку с подготовкой среды. У старого нативного ПО и .NET Framework остаются ограничения длины путей:

   ```bat
   git clone --branch codex/autovedenie https://github.com/9lamal9-pixel/trainer-2es6.git
   cd trainer-2es6
   setup.cmd
   ```

Скрипт скачает ZIP или их последовательные части .zip.part001, .zip.part002 и далее из закреплённого Release, проверит SHA каждой части и соберёт исходный ZIP потоково, сверит размер и SHA256 каждого архива по версионируемому `dev/config/portable-release.json`, проверит пути и распакует комплект. Для доступа сначала используются переменные текущего процесса GH_TOKEN/GITHUB_TOKEN, затем GitHub CLI, затем настроенный Git credential helper. Токен не записывается в файлы и не печатается. Не передавайте токен параметром команды.

После восстановления скрипт настроит локальные пути компилятора, Git и Python. По умолчанию используется входящий в комплект work/portable_python/python.exe с собственным Lib/site-packages; исторические vendor-пакеты не подмешиваются. Проверяются версия, разрядность, импорт pefile/capstone и работа x86-декодера. При полном комплекте интернет для установки Python-пакетов не нужен. Параметр -PythonExecutable явно выбирает другой Python и имеет приоритет. Только при отсутствии встроенного Python используется установленный Python 3.9+ или py; если его pefile/capstone не работают, создаётся dev/state/python-venv и устанавливаются pefile==2024.8.26 и capstone==5.0.6 с официального PyPI. Дополнительные пакеты анализа optional автоматически не устанавливаются.

Затем последовательно выполняются Doctor, Build (candidate) и Handoff. Они должны завершиться успешно. Нативные сценарии и сам тренажёр во время подготовки не запускаются, реестр скрипт не меняет. Для запуска после подготовки: `trainer.cmd -Action Run`. Нормальный Run/Test может настроить HKCU WorkPath с сохранением предыдущего значения по обычному процессу TrainerDev.

Если Git отсутствует в PATH, укажите его путь. -PythonExecutable нужен только для намеренного использования другого Python:

```bat
setup.cmd -GitExecutable "C:\Program Files\Git\cmd\git.exe" -PythonExecutable "C:\Python313\python.exe"
```

## Офлайн и повторное восстановление

Скачайте все файлы комплекта Release на другой машине, включая все части .zip.part001, .zip.part002 и далее, перенесите их в одну папку и выполните:

```bat
setup.cmd -AssetDirectory "D:\Trainer archives"
```

Этот режим не обращается к GitHub. Все архивы Release, включая дополнение со встроенным Python, обеспечивают автономную подготовку без PyPI. Если вы явно выбираете другой Python, заранее подготовьте его зависимости для работы без сети. Офлайн принимаются как целые ZIP, так и полный набор их частей; входная папка не изменяется. Архивы онлайн-режима сохраняются в dev/state/portable-downloads для повторного использования. Уже проверенные части сохраняются между попытками загрузки; после успешной сборки и проверки целого ZIP его части в управляемом кэше удаляются для экономии места.

Существующие одинаковые файлы пропускаются. Если хотя бы один файл комплекта отличается, восстановление останавливается до копирования файлов: текущая работа не перезаписывается. Используйте свежий clone или перенесите свой изменённый файл отдельно. Не удаляйте свои изменения вслепую. Конфигурации environment.json, python-tools.json и environment-context.json намеренно получают пути текущей машины. В relocation.json обновляется только рабочее поле workspace_root; source_root и происхождение переноса сохраняются; предыдущие версии сохраняются в dev/state/portable-config-backup-*. Исторические отчёты и происхождение файлов не переписываются.

`-SkipValidation` выполняет только проверенное восстановление архивов и сохраняет текущие конфигурации; Doctor, Build, Handoff и настройка Python пропускаются. Этот режим предназначен для проверки архивов/восстановления файлов и сам по себе не означает готовность к работе.

## Ограничения

Штатные DLL и ресурсы доступны как полученные файлы; их загрузка не создаёт отсутствующие исходники. Сборка и работа WinForms/.NET Framework x86 требуют Windows. Наличие полного 3D-комплекта не означает, что его сетевой мост и рендер уже интегрированы с текущим управляемым хостом. Полный объём и состав снимка задаёт portable-release.json; новые бинарные изменения требуют нового снимка Release и обновления SHA в манифесте.

## Обновление комплекта сопровождающим

На машине с полным комплектом создайте новую выходную папку внутри dev/archives и выполните pack_portable_environment.py, затем finalize_portable_environment.py с одинаковыми --root/--out/--git. Упаковщик исключает файлы Git и новые редактируемые исходники, проверяет контрольные суммы штатных DLL, ограничивает части 512 МиБ несжатых данных; финализация сохраняет пустые каталоги. Готовый portable-release.json нужно скопировать в dev/config, проверить восстановление, сохранить и отправить коммит.

Publish-TrainerRelease.mjs — средство сопровождающего, требует Node.js. Параметры: --assets <папка>, --commit <полный SHA отправленного коммита>, --notes <UTF-8 файл описания>, при необходимости --git <git.exe>. Без --publish создаётся draft и загружаются проверенные файлы. После проверки --publish публикует предварительный Release; --verify только проверяет существующий выпуск. Токен берётся из текущей авторизации Git/переменных процесса. У опубликованного выпуска файлы не заменяются. Для нового снимка нужны новый тег и согласованное обновление закреплённого тега в скриптах и манифесте.

Для скачивания, временной распаковки и готовой копии рекомендуется не менее 20 ГиБ свободного места. Выбирайте короткий путь к clone, например C:\trainer: старые компоненты Windows/.NET могут ограничивать длину путей.
