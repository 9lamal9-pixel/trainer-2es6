# Модули и границы проверок

Каталог описывает сохраненную интеграционную оболочку C# и штатные нативные модули тренажера. Это WinForms/.NET Framework x86; оболочка соединяет оригинальные Delphi DLL, управляет циклом и содержит обратимые исправления в памяти процесса. Нативные DLL находятся в копии `work/trenager_static/WORK_TRENAGER_3D`, исходная установка `E:\WORK_TRENAGER_3D` не используется для сборки исправлений.

Пути в `dev/config/modules.json` и `dev/config/probes.json` отсчитываются от корня рабочей папки. Исходники в `outputs` остаются общей точкой редактирования для текущих сборок. Их перенос требует одновременно обновить сборку, зависимости и связанные пути данных. Исходники проверок находятся в `work/pneumatic_live_fix/analysis`.

Профиль `integration` содержит первые восемь модулей. Профиль `candidate` дополнительно включает семь пневматических модулей. Профиль `standalone` собирает только явно перечисленные зависимости конкретного стенда. Общие ссылки: `System.Windows.Forms.dll`, `System.Drawing.dll`, `System.Web.Extensions.dll`; нативные проверки обязательно собираются x86.

## Штатные нативные системы

| DLL | Роль |
| --- | --- |
| `LOCOMOTIVES/1/Communication1.dll` | Пульт, графические органы управления, обмен с внутренними объектами и экранами. |
| `LOCOMOTIVES/1/Pult1.dll` | Электрические схемы, реле/контакторы, команды и обратная связь оборудования. |
| `LOCOMOTIVES/1/Tyga1.dll` | Штатный расчет тяги и электрических величин ТЭД. |
| `LOCOMOTIVES/1/MSUL_MON.dll` | Штатные изображения и логика отображения МСУЛ. |
| `LOCOMOTIVES/1/SoundsMSUL.dll` | Звуковая подсистема МСУЛ, подключаемая штатными модулями. |
| `TormModel.dll` | Нативные КМ/ВР, поездная ТМ и пневматические состояния вагонов. |
| `POEZD.DLL` | Движение состава, силы, скорость, координата, профиль пути. |
| `KLUB_U_LCD_XE2.dll` | Штатный блок безопасности и изображение центрального БИЛ-УТ. |
| `SoundsTren.dll`, `TalkSound.dll` | Звуки тренажера и диспетчерский канал. |
| `CalcOgr.dll`, `Saut_Dll.dll`, `AVP.dll` | Ограничения, САУТ и грузовое автоведение. |
| `KPD_3PV.dll` | Резервный прибор скорости/регистрации, инициализируемый оболочкой. |

Communication загружает связанные локомотивные DLL согласно штатной конфигурации; зависимость не означает, что оболочка повторно инициализирует их независимо. Исходные DLL сохраняются как бинарные зависимости. Guards требуют конкретных SHA-256 Pult1, Communication1, TormModel и POEZD; иных версий нельзя считать взаимозаменяемыми.

3D-движок не установлен. Все перечисленные системы работают в существующем стенде без отдельной 3D-сцены; компьютерное управление интерфейсом не используется.

## Проверки

`probes.json` содержит 30 существующих проверок с исходниками, точным классом входа, дополнительными зависимостями и именами результатов. Указанный `legacy_build_script` нужен для происхождения проверки: некоторые старые сборочные скрипты сами запускают EXE, поэтому новый runner должен собирать исходники напрямую.

Основной `smoke`: `ColdNoSource`, `SectionPantographPressure`, `CandidateAirHost`. Полная текущая регрессия добавляет `ColdTrainAuxiliary`, `VcuAirSequence`, `CompressorPrepared`. Эти шесть проверок входят в наборы автоматической регрессии. Текущие диагностические проверки разрешены для отдельного исследовательского запуска и не включены в наборы; устаревшие и небезопасные записи выключены.

| Проверка | Значимые утверждения |
| --- | --- |
| `ColdNoSource` | В 1000 шагах без источников все 77 native узлов ТМ/ТЦ/ЗР и ПМ/УР остаются у нуля. |
| `SectionPantographPressure` | Физическая РС6 каждой секции управляет своим токоприемником; 7 фаз падения и гистерезиса имеют assertions. Четыре комбинации подъема пишутся в JSON `rows` и дополнительно должны проверяться runner. |
| `CandidateAirHost` | Автоматическое/независимое торможение, отпуск/удержание/восстановление, отключение тележки, объекты приборов ПМ/ТЦ и уменьшение native тормозной силы. |
| `ColdTrainAuxiliary` | После сухой сети КМ2 заряжает РС6/РС7 первой секции до 3.5; ПМ и все тормозные узлы остаются сухими, баланс массы выдержан. |
| `VcuAirSequence` | Native событие ВЦУ, безопасное снятие ключа после разрядки головы и хвоста, удержание ИМ и тормоза в II/III, отпуск после возврата I; режим R1 и 4..4.5 у всех 75 вагонов. |
| `CompressorPrepared` | Подготовленная native схема дает разрешение основных компрессоров; два цикла 7.5/9, разгрузка BB 12 с, отключение по БВ. |

Успех требует нулевого кода выхода, выполнения assertions и новых ожидаемых файлов результата. Поле `passed` есть не во всех старых JSON, в частности `VcuAirSequence` его не записывает. Отсутствие поля само по себе не означает неуспех; старый JSON из предыдущего запуска не является доказательством нового прохождения.

В `SectionPantographPressure.rows` записи идут в порядке `(first, second) = (0,0), (0,5), (5,0), (5,5)`. Ожидаемые первые две позиции `feedbacks`: `00`, `01`, `10`, `11`; позиции 3/4 остаются нулевыми для двухсекционного стенда. `native_line_voltage` равняется `0` для `00` и `3100` для остальных. Это проверяет давление источников и связи модели, не пневматические расходы приводов.

Старые `PantographPressure`/`FourPantographPressure` писали общий `TPult.BD`; после раздельного источника РС6 они устарели. `AuxiliaryAirNative` и `ColdControlAirNative` ориентируются на прежний алгоритм и guards. `TwoSectionPneumatic` строит отдельный старый мост без текущего Candidate-модуля. Они сохраняются как история исследования, но не входят в регрессию.

`ColdNativeInitialization` помечен `unsafe`: режим `fresh` повторно вызывает `InitNew` и ранее падал в финализаторе GDI/StringFormat после записи результата. Автоматический запуск отключен. Холодные регрессии используют `InitSostavClass` с временной нулевой уставкой и не повторяют `InitNew`.

Остальные диагностические стенды уточняют гипотезы: фикстуры давлений, трехузловые цепи, искусственные утечки, режимы ВР, временный порог зарядки, формулу трения. Успешная диагностика не подтверждает соответствие точному стенду Р008 или полной подготовке электровоза.

## Открытые границы модели

Доступное РЭ 2008 года и найденные технические материалы пока не устанавливают точную комплектацию электровоза с №137. Все численные допущения следует сохранять вместе с источником и областью применимости.

Не завершены: положительный полный холодный пуск до зарядки ПМ, расход воздуха приводами и катушечные/пневматические пороги КЕБ, профиль DEN, давление-зависимая кривая КМ2 и выбор секции/кабины, полный баланс native вагонного воздуха, контракт массы авторегулятора, абсолютная сила/материал колодок, геометрия утечек/проходов, соответствие отображаемых пикселей и внешнего оборудования. Для исправлений этих областей необходимо добавлять отдельные проверяемые сценарии и сохранять их ограничения.
