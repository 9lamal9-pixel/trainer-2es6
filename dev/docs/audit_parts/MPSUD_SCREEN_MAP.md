## Два монитора, enum и клавиатуры

RTTI `TWindowType` начинается RVA `199548`: значения0..23. RTTI `TMSUD_BTN` RVA `19968C`: `0=None,1=Enter,2=Clear,3=Minus,4=Plus,5=Down,6=Up,7..16=цифры9..0`. Таким образом, цифровая клавиша `n` передаётся байтом `16-n`. Штатные направления/Enter/Clear не равны цифровым клавишам.

`UpdateButtonMSUL(1EF904)` передаёт `TPult+53` левому `TWindowMonitor`, `TPult+54` правому и затем обнуляет оба слота. Сам `SetButton(1F1A84)` сравнивает байт с последним `monitor+15`, сохраняет новый и только ненулевой изменившийся байт отправляет в `GetWindowType(1F036C)` → `SetWindType(1F1AE4)`. Чтобы повторить одну и ту же клавишу, после её цикла нужен отдельный цикл с key=0: иначе повтор подавляется, несмотря на обнуление TPult после предыдущего dispatch. Дополнительный ряд host сейчас пишет одну клавишу сразу двум мониторам (`TrainerIntegrationHost.cs:29`); в проверке отдельных адресатов работать с одним слотом и контролировать второй.

В `TMSULClass` ссылки на мониторы находятся `+20/+24`. В каждом monitor:

| Поле | Назначение и доказательство |
|---|---|
| `+0C` | Общая `TMSUL2ES6`, переданная конструктору |
| `+14` | Текущий `TWindowType` |
| `+15` | Последний байт клавиши для edge filtering |
| `+18` | Номер монитора1/2 |
| `+1C` | Ссылка на `TMainMSULForm` |
| `+20` | Текущий `TWindowWizard`/производный window |
| `+24` | Прежний `TWindowType`, для отката |

У wizard `+0C` — активный frame (`TWindowWizard.Proceed(1E62A8)` и конструкторы производных окон). У формы `+39C` — monitor, `+260` — уже созданный HWND (`VCL.TWinControl.GetHandle(9B958)`). Наличие/класс/поток HWND проверять Windows API и текущими SHA. Не произвольно вызывать Delphi-метод с неверным calling convention.

`SetWindType` игнорирует0, сохраняет прежний enum, записывает текущий и делает `PostMessage(hwnd,0x664,wParam=enum,lParam=0)`. Текущий байт до обработки этого сообщения ещё не доказывает смену frame. `ProceedMonitor(1F1A48)` отправляет `PostMessage(hwnd,0x665,0,0)`.

## Безопасная точка кадра

Старый `Image.FromHbitmap` после общего `DoEvents` не принимает экран: native cab UI мог уже потребить/освободить bitmap, а исходный TPult-слот ещё ненулевой. В [MPSUD_DISPLAY.md](C:/Users/sibir/Desktop/Макрос/Тренажер/dev/docs/audit_parts/MPSUD_DISPLAY.md) разобрано `Communication1.TDrawAlienBitmab.Paint(2A8EB8)` → `DeleteObject` на`2A8F4D` → очистка component+298; TPult очищается позднее на следующем Proceed. `GetObjectType=7` не устанавливает владение и безопасное время копирования.

Штатный producer находится в `TMainMSULForm.WMUPDATE(1EEF10)`: `GetFormImage(11C628)` → `TBitmap.ReleaseHandle(73160)` → запись HBITMAP в TPult+105/+109 (`1EEF82/1EEFD9`) → освобождение уже отсоединённого TBitmap. Новый кадр создаётся только при нулевом соответствующем слоте. Export `ProceedMsul(1F3920)` лишь запускает UpdateButtonMSUL и **PostMessage**; прямой вызов без обработки UI сообщений не создаёт нового bitmap.

Предпочтительная проба без физической правки DLL:

1. В обычном новом процессе успешный штатный StartNative, Show/DoEvents, остановленный managed timer; необходимые тёплые циклы выполняет root. Проверить SHA/path всех DLL, actual TPult owner. Старые кадры потребить обычным UI/Communication и дождаться slot=0; не обнулять чужой живой handle.
2. Найти текущий TMSULClass: export ProceedMsul читает pointer по `modulebase+20BB9C`, затем object по этому pointer. Читать ссылки на левый/правый monitor по `TMSULClass+20/+24`, ссылку на form по `monitor+1C`, уже созданный HWND по `form+260`; проверить IsWindow, classname и принадлежность текущему процессу/потоку. `GetHandleMSUL` использовать нельзя, см. ниже.
3. Передать только нужному монитору byte-клавишу, вызвать existing ProceedMsul. Адресно обработать **только** queued messages `0x664..0x665` конкретного HWND через `PeekMessage(...,PM_REMOVE)`/DispatchMessage, сохранив порядок. ## Обнаруженные ограничения интерфейса

**S-API-01: GetHandleMSUL — stub.** Export `1F393C`, length12: `push ebp; mov ebp,esp; push ecx; mov eax,[ebp-4]; pop ecx; pop ebp; ret4`. Параметр не читается, локальный result не инициализируется. Нельзя считать return HWND или вызывать на его основе SendMessage. Это дефект диагностического API текущей DLL; отсутствие экранов отсюда не следует. Безопасный read-only путь — actual monitor/form+260 с guards.

**S-MENU-01: enum шире фабрики.** Messages/Marshrut/Archive/PCH/Caloriffer/PU нельзя объявлять существующими отдельными экранами по enum.
