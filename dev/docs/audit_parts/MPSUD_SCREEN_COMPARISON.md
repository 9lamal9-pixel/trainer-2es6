## Подтвержденные расхождения и действия

### SC01 — ведомые Ia/Iv выбираются из одной группы вместо максимума

**Где:** `TwtMashinistFrame.ProceedCur` RVA1CBC08; текущий ASM `work/mpsud_screen_values/TwtMashinistFrame_ProceedCur.asm`; цепочки опубликованы в VALUES. При ненулевом raw Ia первой группы выбирается первое среднее Ia/Iv секции, иначе второе. Max не вычисляется.

**Доказательный пример:** Ia2=433/444 А, Iv2=533/544 А, raw первой группы!=0 → renderer 433/533. Норма для ведомой секции требует 444/544 в этом положительном примере. **Как должно быть:** вычислять действительный максимум активных групп отдельно для Ia и Iv; сохранить отдельные токи ведущей секции. **Источник:** РЭ2 §1.7.3.1, лист49, [R21](https://zinref.ru/000_uchebniki/04600_raznie_6/358_Elektrovoz_2ES6_rukovodstvo/021.htm). Высокая уверенность в статическом отклонении; end-to-end пока **NOT_EXECUTED**.

### SC02 — СИ содержит псевдоизмерения и фиксированные величины

**Где:** `TwtCIFrame.UpdateData` RVA1DE9FC–1DF33F, `work/mpsud_screen_values/TwtCIFrame_UpdateData.asm`. UЭДТ = Round(Pos×2800/65), без чтения Udvig+33; I собственных нужд=0; I ПТР=Ia/4. Из PSN-флага получаются генератор0/5 А, борт110 В, АБ110/140 В и −5/0 А. Riso фиксированы33.3/33.1/0.46 (последнее печатается0.5).

Это доказанный дефект представления этих полей как актуальных измерений; он не доказывает неисправность всей физической модели. Например, Pos23/Udvig1777.25 дает UЭДТ991 независимо от реального Udvig. **Как должно быть:** передавать измеряемый параметр соответствующего датчика; отсутствующую модель явно обозначать как отсутствующие данные. Это инженерное применение назначения СИ, а не восстановленный точный вид отсутствующего рисунка. **Источник:** РЭ2 §1.7.8, листы67–68, [R22](https://zinref.ru/000_uchebniki/04600_raznie_6/358_Elektrovoz_2ES6_rukovodstvo/022.htm); подробный состав/единицы всех его строк — **SOURCE_GAP**. Исправлять путем замены константы другой константой недостаточно.

### SC03 — счетчик энергии всегда показывает нули

**Где:** тот же CI.UpdateData: frame+404/+408/+40C/+410 получают строки0 при каждом обновлении. **Как должно быть:** источник накопленной потребленной/возвращенной энергии, согласованный со временем модели; при отсутствии счетчика — явное отсутствие данных. **Источник:** назначение счетчика в РЭ2 §1.7.8, лист68, [R22](https://zinref.ru/000_uchebniki/04600_raznie_6/358_Elektrovoz_2ES6_rukovodstvo/022.htm). Статическая заглушка подтверждена, полный рисунок/формат и runtime не приняты.

### SC04 — общие давления/секционные ограничения СИ; скорость требует нормы единиц

**Где:** CI.UpdateData обходит только section1/2; обе колонки получают общий Loc.GR/Loc.TC/головной TVagon.TM; ЦУ вычисляется как GR−1, ТЦ1/ТЦ2 — одинаковый Loc.TC. **CONFIRMED_COMMON_SOURCE / SOURCE_GAP:** общий источник доказан, но совпадение двух реальных давлений в определенном состоянии само по себе не является дефектом. Подстановка ЦУ=GR−1 — расчетная заглушка вместо чтения отдельного давления. **Как должно быть:** источник фактического давления соответствующей цепи/секционного датчика либо честное ограничение модели. Подробное назначение строк РЭ2 §1.7.8/рис.1.29 остается **SOURCE_GAP**; нельзя утверждать отсутствие всех секционных тормозов по этому экрану.

Строка native CI.Init называется «Скорость от БЭС» (RVA1DE2C8), единицы не указаны. Renderer читает Round(Tyga.V) без×3.6; Tyga.V — signed m/s, host Input.Vcur — km/h (`TrainerNativeSystems.cs:63`). **UNIT_RISK**, не окончательный нормативный дефект: [R22](https://zinref.ru/000_uchebniki/04600_raznie_6/358_Elektrovoz_2ES6_rukovodstvo/022.htm), §1.7.8, лист67–68, не дает единицу этой строки вне рисунка. Ее нужно сначала установить и явно подписать.

### SC14 — контактные виды режима/управления повторяют названия сигналов

### SC15 — ПСН/РН3000 не получают актуальные состояния в штатном пути отрисовки

**Область доказательства:** весь опубликованный набор процедур `TwtPCConnectFrame`/`TwtPSConnectWindow` и `TwtRN3000Frame`/`TwtRN3000Window`, включая конструкторы, обе RN DrawCell и все четыре PC DrawCell. Свежие диапазоны текущей DLL и SHA сохранены в [манифесте](C:/Users/sibir/Desktop/Макрос/Тренажер/work/mpsud_screen_sources/static_gaps/manifest.json). Это расширяет первоначальное наблюдение stub; скрытый внешний getter не предполагается по одному пустому методу.

**РН3000:** DrawGrid1DrawCell **1E22AC** и DrawGrid2DrawCell **1E23FC** читают только записи frame: ShortString name bases **+91C/+2BC**, byte flag bases **+981/+321**, stride **102 (0x66)**. Положительный flag разрешает зеленую заливку индикатора; актуальные MSUL records/внешние accessors не читаются. Init **1E254C** задает геометрию и копирует постоянные подписи, включая вторую копию названий через ShortString helper **7368**; флаги состояния этот метод не записывает. ProceedFrame **1E291C** только инвалидирует две таблицы. UpdateData **1E2964** пустой (10 bytes). SetView **1E2948** пишет лишь view+2B8. Конструктор окна **1E2190**, запись **1E21E0**, сохраняет указатель TMSUL2ES6 в frame+2B4, но ни один рассмотренный метод frame его не читает. Window.Proceed **1E225C** вызывает пустой базовый Proceed **1E62A8** и только указанный ProceedFrame; Window.SetView **1E2290** пишет window+10. Альтернативной ветви обновления флагов в этих классах не найдено.

**Связь ПСН:** DrawGrid1/2/3/4DrawCell **1E15C8/1E16B4/1E17A0/1E188C** формируют текст исключительно из глобальных ShortString-таблиц **VA60B379/60AB30/60B443/60B50D** со stride101. Ни один из четырех обработчиков не читает статус/готовность/обмен из native records и не рисует зависящий от них индикатор. Init **1E1978** задает только геометрию; ProceedFrame **1E1A60** инвалидирует четыре таблицы; UpdateData **1E1ACC** пустой; SetView **1E1AB0** меняет лишь view+2D0. Конструктор окна **1E14AC**, запись **1E14FC**, сохраняет MSUL pointer+2CC, далее он не читается. Window.Proceed **1E1578** также вызывает пустой base и invalidate. Само наличие указателя/подписей не является передачей показаний.

**STATIC_MISMATCH, высокая уверенность в рассмотренном штатном пути:** интерфейс не связывает показания с актуальным обменом. **Как должно быть:** состояния готовности/нарушения обмена ПСН, БС-УВ/РН3000 и работа отдельных РН3000 №1/№2 должны отражать соответствующие входные данные. **Источник:** РЭ2 §1.7.10, лист70 и §1.7.11, лист71, [R22](https://zinref.ru/000_uchebniki/04600_raznie_6/358_Elektrovoz_2ES6_rukovodstvo/022.htm), рисунки1.31/1.32.

**Границы:** полный состав строк, конкретные неисправности/цвета каждого элемента на исходных рисунках — **SOURCE_GAP**. Динамический опыт изменения native данных/потери связи с проверкой каждого индикатора — **NOT_EXECUTED** этим исполнителем; root-галерея подтверждает доступность окон, не эту реакцию. Начальное числовое значение RN flags и произвольные внешние записи по непубличному frame pointer не принимаются данным статическим разбором. Дефект показаний не доказывает отсутствие физического регулирования РН3000 или ПСН.

## Важные отрицательные границы вывода

Uкс на Mash/CI читается из **TResTyga.Uset+11**, не из TShema.Useti+125. Поэтому C07 с записью3100/0 в Pult→TShema нельзя автоматически объявлять доказательством постоянного числа3100 на мониторе: необходима вся цепь передачи в ResT. Свежая fixture с ResT3123.25/Shema3299 должна доказать выбранный renderer source, отдельно от физического генератора напряжения.

Сохраненный Ia в Tyga может обрезаться до750 после вычисления силы (TR-01). Это требует одновременной проверки физического тока/силы/показания; существование барграфа и корректное форматирование не принимают калибровку тяги. Нет оснований объявлять всю защиту>800/10с отсутствующей только по одной операции Tyga.

DefaultCaption=«ТМ» у индикаторов в DFM не является доказанным дефектом рабочей подписи: runtime update меняет состояние/текст. Количество опубликованных DrawGrid также не принимает их видимость. Цифровые assertions fixture, совпадающие с константами/ошибочными mappings, означают успешное воспроизведение **текущего дефекта**, а не соответствие РЭ.

В новом результате должны быть отдельные поля: module identity, доступность frame/view, bitmap capture, current renderer expected/actual, normative expected/actual, fixture restoration. Новая галерея root использована для наблюдений SC13/SC14; остальные свежие числовые результаты основной исполнитель сохраняет отдельно. **PENDING_ROOT** не заменяется нормативным PASS на основании успешного захвата картинки. Для SC01–SC15 заданы кодовые доказательства и ожидания; полнота всех нормативных рисунков по-прежнему ограничена SOURCE_GAP.
