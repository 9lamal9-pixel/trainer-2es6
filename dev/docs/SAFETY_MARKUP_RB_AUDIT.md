# КЛУБ, САУТ, локомотивный светофор и РБ

Рабочая интеграция использует штатные WinForms/.NET x86 и native DLL. Результаты ниже относятся к комплекту из `work/trenager_static/WORK_TRENAGER_3D`; соответствие каждой комплектации РЭ 2ЭС6 начиная с №137 ещё не подтверждено.

## Источник пути

Полный курс `Тюмень — Екатеринбург` взят из `work/native_distribution/WORK_TRENAGER_3D/RAZMETKA/Voiniovka - Ekat`. Проверенный снимок хранится в `dev/config/native-markup/Tumen_Ekaterinburg.source.json`, SHA256 `BF11DB8D35391B7A3CBF3DC02F96C8AB08B0B6237A7DD5AEE4049C093F809728`.

Снимок содержит 181 светофор, 224 участка профиля, 177 кривых, 27 станций и 3273 записи пикетажа. Координата разметки возрастает от начала курса. Она не совпадает с осью PDF-карты; преобразование между ними не придумано. Полный профиль заканчивается на 333033 м; Кокшаровский находится на 191500 м.

Исходный `.ogran` не содержит ограничений. Предел 80 км/ч в этом режиме задан явно для учебного сценария. Показания светофоров берутся из сохранённых состояний либо изменяются оператором кнопкой «Задать сценарий». Источник не содержит действующей занятости блок-участков. Проезд запрещающего фиксируется источником; изменение цвета не снимает эту фиксацию. Новая начальная станция сбрасывает только состояние источника, не защиту ЭПК.

Поля `Nach/Long/Radius/Hkr` плана подтверждены loader `2647C8` и RTTI `TPlanE`. Native POEZD `SetPlan27F8` использует абсолютный радиус через helper `114D0`. Сохранённый `Hkr` не выдаётся за результат штатного пересчёта возвышения рельса.

## Связь приборов

Имена передаются как штатный shortstring20: Windows ACP через `GetACP` и `WideCharToMultiByte(flags0)`, один байт длины и максимум20 ANSI-байт. Фиксированная CP1251 не подставляется.

Первичные поля `TCurLighterRec` занимают первые 35 байт. Последующие `Dist/Uklon/DeltaS/Vpr/Vcel` вычисляются native приборами. У КЛУБ, САУТ, CalcOgr и native АВП теперь отдельные входные записи и отдельные производные поля. Это исключает запись результата одного прибора в состояние другого. Выход САУТ также изолирован: native САУТ является его единственным производителем; managed интеграция читает фактическое торможение, перекрышу и запрет тяги.

В выбранном режиме КЛУБ альтернативный КПД не инициализируется. Оригинальный `GeneralPB.Proceed330DB8` создаёт и вызывает КПД только при наличии выбранного provider. Ранее безусловный запуск КПД порождал его запрос бдительности рядом с КЛУБ и влиял на ЭПК.

Штатная проекция локомотивного сигнала подтверждена в Main EXE: `3E4D60/3E3B24` передают фактический native `PBOut+20` в `Input+1D`. Код не выводится непосредственно из цвета путевого светофора. Значения 0/1/2/3/4/5 обозначают выключено/З/Ж/КЖ/К/Б. Красный путевой сигнал кодируется `CodeWay3` при приближении; после проезда исчезновение кода обрабатывает сам native КЛУБ.

Основной пульт получает native bitmap КЛУБ: `Out+32 → SetHndlKLUB2AEFDC → cab+508 KLUB_DAB`. Аппаратные индикаторы и ПОМ читают `Input+1D`. ABI и адреса сохранены в `dev/config/native-markup/native-abi-evidence.json`.

Декодер КЛУБ имеет штатные условия запуска: ключ ЭПК включён, движение в некодированной зоне выключено, выбран обычный режим и нет ошибок ограничений. После включения питания счётчик `cntVklEpk` квалифицирует запуск примерно за 50 native циклов; белое показание в это время не является доказательством неисправной разметки.

## РБ и ЭПК

Native `TPBBtnPos` содержит отдельные РБ/РБС/РБП в байтах 0/1/2. Периодическая проверка КЛУБ требует РБС; первоначальные проверки допускают группу кнопок согласно native режиму. САУТ принимает РБ или РБС, а не РБП. Для РБП проверен программный операторский вход штатного потребителя; физического устройства РБП в этой приёмке нет.

Программные кнопки включаются явно и работают только при удержании. Отпускание клавиши, потеря фокуса, потеря захвата мыши и деактивация окна снимают собственное нажатие. Уже нажатая физическая кнопка сохраняется. Автоматического подтверждения бдительности в рабочем коде нет.

`PBOut+30` — штатное предупреждение против длительного удержания, а не запрос подтверждения. Оно устанавливается на 71-м последовательном native вызове при удержании любой кнопки и снимается после отпускания всех кнопок.

Защита ЭПК подключена точной копией функции `TGeneralPB330EDC` в памяти с SHA/byte guards, переносом вызовов и констант и RX-защитой. Managed код записывает только собственный снимок реальных входов; катушку, свист, срыв и КОН меняет оригинальная функция. TormModel формирует давление камеры из реального ПМ: зарядка/разрядка по 0.1 за native цикл, минимум 1.0. При снятой катушке и давлении ниже 1.5 native функция устанавливает срыв. Поздняя РБС его не сбрасывает.

Подготовка испытания выполняется штатными действиями: обслужить начальный запрос РБС, выключить ключ, дождаться измеренной зарядки камеры, включить ключ и подтвердить новый запрос. Давление и выходы защиты для получения успешного результата не подставляются.

Экранный пульт выбирается через штатный `RIT.VirtPult+83` до `InitCommunication`. Настройка меняется только в памяти и восстанавливается после успешного native close. `CommOwner+10` — настоящий указатель аппаратного provider; интеграция его не подделывает. Наличие потенциальной аппаратной перезаписи команд само по себе не доказывает её участие в конкретном отказе АВ.
