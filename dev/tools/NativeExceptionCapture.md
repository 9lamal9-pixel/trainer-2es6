# Захват исключений инициализации

Проба **отключена, kind=unsafe** после первого полезного захвата 11 октября 2026: `EInOutError`, `Invalid file name - %s`, throw RVA `1AE65D` внутри `Communication1.SaveLocoType`. Затем работа под debugger вызвала повторные noncontinuable exceptions `C0000025` и аварийное завершение CLR `80131506`. Повторять native debugger capture для приемки запрещено; первый captured exception достаточен для статического расследования. Инструкция ниже сохраняет происхождение инструмента, а не разрешает новый запуск.

`NativeInitializationCapture` — диагностическая проба, запускаемая через `TrainerDev.ps1 -Action Test -Probe NativeInitializationCapture`. Она записывает свежий `results/Trainer_native_initialization_capture_ready.json` с PID и каталогом сессии, затем 20 секунд ожидает отладчик перед обращением к `Handle` и обычным `StartNative`. При отсутствии отладчика native модель не запускается. При наличии отладчика выполняется только обычная candidate инициализация, без пневматического сценария и дополнительных патчей.

`NativeExceptionCapture.cs` — отдельный x86 отладчик только для этого deployed EXE в текущей папке `outputs`. Сборка не запускает модель:

```powershell
& .\dev\tools\BuildNativeExceptionCapture.ps1
```

Запустите выбранный `Test` отдельно, прочитайте **новый** ready JSON и подключите helper в пределах 20 секунд. Не используйте старый PID/ready файл:

```powershell
& .\outputs\NativeExceptionCapture.exe $captureTargetPid $captureLogPath $captureWorkspaceRoot 75
```

Параметры: PID диагностической пробы, новый JSONL файл внутри текущей среды, абсолютный корень среды, таймаут helper в секундах. JSONL создается через `CreateNew`, чтобы не заменять прежние доказательства. Рекомендуемое расположение — `<новый probeFolder>/native-first-chance.jsonl`.

Helper читает события загрузки модулей, адреса исключений и параметры, EBP frame chain и ограниченный участок стека. Для Delphi `0x0EEDFADE` сохраняет адрес броска из первого параметра, объект исключения из второго параметра, classname из VMT и Unicode `FMessage`. Поля класса/сообщения и frame chain — чтение известных структур этого x86 Delphi build; неудача чтения сохраняется без изменения процесса.

Helper теперь возобновляет событие и отсоединяется сразу после первого Delphi exception. Дополнительные ограничения: 4096 debug events, 64 application exceptions, три повтора одного exception code/address/chance/thread; `C0000025` тоже немедленно останавливает захват. Повторные записи компактны и не перечитывают объект/стек. Эти guards сокращают воздействие отладчика, но не доказывают безопасность нового native запуска.

Приложению передается `DBG_EXCEPTION_NOT_HANDLED` для всех его exceptions. `DBG_CONTINUE` применяется только к созданному Windows начальным breakpoint подключения отладчика в `ntdll`; остальные события возобновляются обычным образом. Helper не меняет память, регистры, реестр или DLL, не закрывает окна и не завершает целевой процесс. На таймауте отсоединяется; `DebugSetProcessKillOnExit(false)` сохраняет целевой процесс при завершении helper. Таймаутом/cleanup самой пробы управляет штатный `TrainerDev Test`.

Присутствие отладчика меняет среду процесса. Этот запуск дает диагностические сведения, но не заменяет новый успешный запуск требуемых сценариев без отладчика. Код 1114 означает отказ загрузки/инициализации DLL; код 200 означает перехваченное исключение внутри экспортированного `InitCommunication`. Захват нужен для определения точного исключения, а не для обхода отказа.
