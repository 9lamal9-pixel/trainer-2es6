# Traction.cs: интеграция для 0.7.4

## Основа и причина интеграции

Входной файл `incoming/Traction.cs` взят из `Trainer2TE116_Realistic_Patch_0.7.2 (1).zip`. Его непосредственная замена не собирается с существующим проектом: он удаляет `Init`, `Step`, `SetFault`, `ConditionCurve`, `FaultList`, управление компрессорами, батареей, лампами и диагностикой; дублирует поля и методы существующего `SchemeLink.cs`; объявляет отсутствующий тип `Circuits` вместо используемого `Scheme`.

Рабочий `src/Traction.cs` поэтому восстановлен из подтверждённой базы `baseline_0.7.2/src/Traction.cs` (после применения версионного патча 0.7.2). В него перенесены совместимые изменения непрерывной модели из входного файла. Сохранены API, тип `sealed partial Traction`, единственная реализация электрических решений в `SchemeLink.cs`, пуски, защиты, неисправности, управление аппаратами, лампы, звуки и токи собственных нужд.

## Перенесённые изменения

- Состояние синхронного возбудителя `ExciterField` перед существующим состоянием обмотки возбуждения ГГ `Field`; постоянная времени из входного патча 0,18 с.
- Коэффициент токовой коррекции потолка возбуждения `tkCompoundK = 0.12`, как во входном файле.
- `SuChannel`: активное ограничение тока/мощности/напряжения либо аварийное возбуждение, рассчитанное по фактической ветви существующего селективного узла.
- Оценочные показания `IdAnchorMm`, `IdImpedanceOhm`, `FuelRack`. Для ИД использована предложенная входным файлом шкала 0–65 мм, 5,5–70 Ом. Они обновляются согласованно с `IdK` при создании, инициализации и расчёте. Это производные модельные показания, не независимо откалиброванные измерения реального регулятора.
- Добавлен сброс нового состояния возбудителя и новых активных показаний в существующий `SetState` при остановке/прокрутке/прокачке. Повторная `Init` создаёт новые секции без наследования состояния предыдущей поездки.
- Сохранены таблица мощности по оборотам, темпы 17/14/35 об/мин/с и расход 0,192 из версии 0.7.2; повторная калибровка тяги и топлива не выполнялась.

Все новые фильтры используют ограниченный коэффициент `min(1, dt/tau)`; при положительном шаге они не дают численной экстраполяции за целевое значение. Внешние отрицательные скорости по-прежнему нормализуются существующим `Step` перед физическим расчётом.

## Не перенесённые несовместимые фрагменты

Дублирующие `E`, `SchemePosition`, `SchemeDiesel`, `Direction`, управление лампами и общие электрические поля оставлены у существующего владельца `SchemeLink.cs`. Это сохраняет рабочие задержки пуска и самоподхваты схемы.

Входная ветвь АП заменяла обратную связь постоянным заданием возбуждения `rpmRatio*apK`. При имеющемся сопротивлении силовой цепи и малой скорости такое задание может достигать предела поискового диапазона 20000 А. Без отдельной характеристики аварийного возбуждения и проверки токовых ограничений она не интегрирована: сохранена существующая проверенная структура АП с понижением задания мощности и штатными защитами. Это ограничение интеграции следует сохранить в описании патча.

## Что нельзя утверждать по этим исходникам

Строки входного README о ГП-311Б, паспортной магнитной характеристике и «четырёхконтурной физической модели» не являются подтверждением соответствующей комплектации локомотива или натурной валидации. Реализация остаётся нормированной инженерной моделью: ИД задаётся `IdK`, его миллиметры/омы выводятся алгебраически; `FuelRack` не управляет фактической подачей топлива отдельным газодинамическим контуром. Код интеграции не вводит утверждение о генераторе ГП-311Б.

## Проверка

Агент интеграции не запускал сборку параллельно: последовательную сборку и общий прогон выполняет родительская задача. Минимальные целевые проверки для нового состояния: `Init`/повторная `Init`, разгон 0→1→13 при dt 0,1/0,02 с, отсутствие NaN/Infinity во всех электрических состояниях, сброс возбудителя при остановке, работа одной/двух секций, снятие возбуждения через защиты, АП, ОП1/ОП2 и отключённые ТЭД. Текущие изменения файла завершены; результат запуска проверок должен быть добавлен из фактического общего прогона.
