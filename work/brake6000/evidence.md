# Библиотеки, тормозная сила и продольная динамика: статический разбор

Все адреса ниже VA при ImageBase=0x400000; RVA=VA−0x400000. Никакой код образцов не запускался. Python выполнял только чтение файлов, декодирование структур и дизассемблирование.

## Декодирование библиотек

`parse_libraries.py` восстановлен по TD32-именованным `LoadFromStream` и setters из `EditLibrary.exe`. Обе библиотеки полностью пройдены; конец парсера точно совпал с длиной каждого файла. Значения с физическими offsets находятся в `libraries.json`.

## Существенное различие массы 2ЭС6

Физическая масса двух секций Direction0=200т. Однако восстановленный путь ПОЕЗД получает **100т на один объект 2ЭС6**,4оси,длину15.965м:

- `TTrain.AddLoco` VA0x62ca68 создаёт один `TLocomotive` и добавляет в EngList/LocoList; цикла по Sec нет.
- `TLocomotive` VMT VA0x61d7b0: +0→GetLength VA0x61f958, +4→GetAxes VA0x61f9d8, +0xc→GetWeight VA0x61fc14.
- GetWeight возвращает `LocoData.Phisics.WightOneSec` без Sec. GetAxes/Length так же возвращают библиотечные значения одной секции.
- InitPOEZD (частная функция, имя inferred) VA0x7293f4, конкретно VA0x729515..0x729535, вызывает virtual GetWeight→float→SetSostav без Sec.
- `Sec=2` хранится отдельно в object+0x140. Пневматика умножает VGR наSec; TC перед SetTorm тоже умножается наSec. То есть два уровня модели используют количество секций по-разному.

Это подтверждено независимой проверкой modules. Для примера с одним объектом2ЭС6 и75платформ ПОЕЗД получается6100т и1110.215м, тогда как реальные два200-тонные секции с теми же вагонами дают6200т и1126.18м. Другой пользовательский способ создания нескольких объектов/правки библиотек здесь не исследован; это не доказательство активного сценария.

## Масштаб силы и ускорение

`POEZD.DLL`:

- SetInitState VA0x402435 переводит скорость км/ч вм/с множителем0.2777777777778.
- SetSostav VA0x4022cf сохраняет scaledMass=0.1*m, m от caller втоннах.
- VA0x401627..0x401652: a_j=(coupler_left−coupler_right+external_j)/scaledMass_j.
- Следовательно единица силы внутри POEZD=10кН. Это не тс; g для уклона отдельно9.81.
- Poezd принимает силу первого элемента float напрямую stack+8→0x41d0a4 (VA0x401263); прибавляет без cap наVA0x401a5b.
- Основной EXE `TPoezdDll.ProceedTPoezdDll` VA0x7299d0: Loco+0x253→float, возможна только инверсия знака направления; VA0x72a120..0x72a12f отправляет её в Poezd. dt=.1с. Дополнительного cap между силой локомотива иPOEZD здесь нет.
- Внутренний шаг POEZD=.01с, вычисляются скорости и координаты всех элементов, с предиктором/корректором; внешняя сила в пределах вызова удерживается. Это не одно уравнение только для головного локомотива.
- Явного множителя вращательной инерции1.06/1.1 в найденном пути mass→a нет.

В установившемся движении с одинаковыми скоростями внутренних элементов средневзвешенное ускорение центра масс: `a=(F_kN−R_kN−B_kN−Grade_kN)/M_t`, м/с². Сцепные силы взаимно сокращаются; ускорение головы во время переходного процесса может отличаться.

## Основное сопротивление, уклон, кривые

Caller выбирает индекс по числу осей: ≤4→1; >4→2 (InitPOEZD VA0x7294b1..0x7294d9).

POEZD VA0x401ee8..0x401f83:

`R_10kN=.001*(C0[idx]+C1[idx]*abs(v_ms)+C2[idx]*v_ms²+7*(.1m_t))`.

Таблица C0=[32,12,48],C1=[1.44,1.44,1.094],C2=[.1296,.1296,.2177]. Для4осного элемента (idx1):

`R_10kN=.001*(12+.4*V_kmh+.01*V_kmh²+.7*m_t)`.

75платформ по80т +один объектLoco100т:

`R_kN=51.82+.304*V+.0076*V²`.

При51км/ч:87.0916кН. Если отдельным исправленным предположением добавить второй100-тонный элемент с4осями, R=88.376кН,6200т. Не подменять этим фактический путь исходной программы.

SetProf VA0x402206: iStored=.001*i_permil. Сила уклона VA0x40208e..0x4020ad: `Fgrade_10kN=-iStored*9.81*scaledMass` → `Fgrade_kN=-.00981*m_t*i_permil`. При6000т вагонов+100т modelLoco и6‰→359.046кН; для6200т→364.932кН. Профиль выбирается под координатой каждого элемента. Кривые VA0x402120..0x402147: `Fcurve_kN=-.7*m_t/R_m`, только когда элемент находится внутри соответствующего участка.

При скоростях головы≤1.5м/с POEZD отдельно обрабатывает смену знака сопротивления и удержание у нулевой скорости; вышеуказанная удобная суммарная формула применима к рассматриваемым51км/ч.

## Давление цилиндров → колодочная сила

Main EXE TTrain.GetPtm VA0x62e6a0, несмотря на имя, возвращает Ptc:

- loco object+0x149=FLocP0x13c+Pnevmo5+PSend.PtcLoc8;
- wagon object+0x45=FVP0x41+VSend.Ptc4.

Доказаны RTTI TLocParam VA0x5fb490,TPnevmo VA0x5fb0c8,TVagonParam VA0x5fa6e4,TVagonSend VA0x5fa5a0; airbrake независимо подтвердил.

В main `ProceedTPoezdDll` RVA0x329a70..0x329c37:

- настоящий локомотив: Psend=CountTC*Sec*Ptc (4*2*Ptc для2ЭС6);
- asWagon ветка исключает дополнительное умножение наSec;
- платформе: Psend=Ptc*min(BreakeToAxis[0]/700,3); гружёное700 даёт1;
- KoefUpTorm по constructor=1 для грузового типа/1.5 дляне-грузового; также учитываются башмаки (+5 за каждый включённый).
- CountTC raw читается именно изlibraryTorm+0x10; constructor отдельно умножает VGR, field+0x18, наSec. Двойного Sec дляCountTC в этих участках нет.

POEZD SetTorm VA0x40229e хранит Psend. VA0x401dbc..0x401edd вычисляет:

`K=A[idx]*Psend*Lever[pad,idx]*.00085`

`B_10kN=phi0[pad]*K*(K+c1[pad])/(K+c2[pad])*(abs(v_ms)+c3[pad])/(abs(v_ms)+c4[pad])`.

Таблицы A=[994,994,1257]; Lever дляpad0=[5.79,5.79,8.245],pad1=[9.03,9.03,12.915]; phi0=[.055,.031]; c1=[20,6.25]; c2=[5,1.92]; c3=[41.7,27.78]; c4=[20.85,5.56]. Код индексирует pad изEngine.FTk, byte object+4. Исправление от2026-10-11: по точному совпадению пяти коэффициентов с опубликованной исследовательской моделью pad0 соответствует композиционным, pad1 — чугунным колодкам. Предыдущее предположение было обратным и неверным. Источник: https://prom-trans.kz/assets/files/zhurnal/1_50.pdf , PDFстраницы19–20, формулы15–17. Это идентификация математических ветвей; явное имя enumFTk не извлечено.

В том же источнике k(t) определено как нажатие на ОДНУ колодку, а суммарная сила равна n*phi(k)*k. NativeDLL использует в нелинейной phi суммарное K всего экипажа. Для локомотива это требует расчёта по отдельным колодкам с давлением соответствующей тележки. Единицы k и коэффициент преобразования nativeсилы должны быть независимо подтверждены перед изменением DLL. Исследовательская статья не заменяет заводское РЭ и не доказывает применимость редакции к №137+.

Дляidx1,pad0: K=4.891971*Psend. Дляidx1,pad1: K=7.629447*Psend. В движенииB противоположна знаку скорости. ПриPtc3.9, V51км/ч, гружёнойплатформе700 иpad0:27.170416кН навагон;75вагонов2037.781214кН при ОДИНАКОВОМ заданном давлении. Для2ЭС6CountTC4,Sec2:146.675180кН при томже Ptc3.9. Это проверка преобразования давления в силy, а не расчёт переходного торможения или тормозного пути; реальные давления во времени даёт пневматическиймодуль.

## Автосцепки

POEZD VA0x40174c..0x4019e5 вычисляет силу по относительному смещению и скорости соседних элементов. Есть свободныйход .065м изcaller, односторонний вычет этого хода, демпфирование, ветки сжатия/растяжения и гистерезисная память предыдущего деформирования/силы. Дляиндекса1 заданные таблицы: stiffness2000,transition.09м,damping100,constant2; масштаб этих внутренних параметров отдельно не верифицирован. Модель передаёт продольные усилия последовательно и хранит экстремумыGetMaxS/GetMaxA. Упрощённый единый a описывает центрмассы в одинаковом состоянии, но не первый удар вцепи.
