# Независимая проверка TrainerRouteDOS.cs

Проверен только `outputs/TrainerRouteDOS.cs`, без редактирования. Схема будущего JSON анализировалась по классам этого файла; фактические данные PDF и ABI DLL этой проверкой не подтверждаются.

## Исправить

1. **График скрывает электрическое торможение.** Сила ограничена `Math.Max(-10, Math.Min(800, force))`. Любая отрицательная сила меньше −10 кН рисуется одинаково у нуля. Для совмещённого графика тяги/торможения нужна отрицательная область и линия нуля; реальные показания не следует заменять −10 кН.

2. **Подпись масштаба давления не соответствует рисунку.** Сила использует делитель 800, давление — 6. Следовательно, одинаковая высота соответствует 800 кН и 6 бар, то есть множителю 133.33, а подпись обещает «ТЦ, бар ×100». Нужно либо отображать `tc * 100 / 800`, либо дать отдельную шкалу давления и убрать множитель.

3. **Текст рекомендации ничем не ограничен.** `DrawString(text, font, brush, x, y)` рисует всю строку без правой границы и переноса. Если рекомендация длиннее доступных примерно 640–850 пикселей, она пересечёт рамку и HUD. Использовать прямоугольник для переноса/обрезки в блоке рекомендации и оставить место для ссылки на страницу.

4. **Ошибка в видимом названии конечной станции.** Заголовок окна и подпись карты содержат «Кошкаровский». Имя предоставленного PDF — «Войновка - Кокшаровский 2ЭС6.pdf». Пользовательские подписи должны содержать «Кокшаровский».

5. **Граница интервалов захватывается предыдущим элементом.** Условия `k > km_end - 0.000001` включают точный нижний конец предыдущего интервала. Первый найденный элемент поэтому сохраняет прежний лимит на общей границе. Корневая задача уже выявила это и готовит исправление. Тот же выбор интервала есть у профиля и рекомендации.

## Компоновка

При поверхности 1200×686: профиль 226–456, рекомендация 466–536, график 546–655, нижняя подпись с 663. При 1000×650: профиль 226–420, рекомендация 430–500, график 510–619, нижняя подпись с 627. Прямоугольники не пересекаются. Правый HUD имеет одинаковую ширину около 300 пикселей в обоих случаях. Строки данных заканчиваются около 434, блок следующей станции около 509; сообщение об ошибке расположено ниже. Постоянные надписи помещаются. Обнаруженное переполнение относится к переменной рекомендации.

## Синхронизация и допущения

- Просмотр/масштабирование меняют лишь область карты. Кнопка начала со станции отдельно вызывает штатный `stateTrain` и очищает след; это соответствует явному изменению начального состояния.
- Координата, скорость, силы, токи и давления берутся из общего состояния тренажёра. Советы для 6300 т не управляют контроллером; фактический состав отдельно указан как 6000 + 200 т.
- Код последовательно использует убывание километров; `direction` допускает только −1. Это корректно лишь при подтверждённом направлении PDF.
- Профиль и ограничения отправляются в штатные модели. Кривые намеренно не моделируются, и это записано в журнале; поле `curves` само по себе ещё не означает, что кривые участвуют в сопротивлении.
- Проверка допускает расхождения границ до 3 м, однако поиск интервалов не закрывает такие реальные зазоры. Если извлечение PDF создаст зазор в пределах этой погрешности, лимит останется последним, а профиль HUD станет пустым. Для фактического JSON требуется проверить точную стыковку или нормализовать её при загрузке.
